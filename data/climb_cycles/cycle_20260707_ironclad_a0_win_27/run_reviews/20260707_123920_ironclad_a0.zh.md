# 单局复盘：20260707_123920_ironclad_a0

## 结论

本局为 Ironclad A0 live MCP 爬塔，结果是 F20 Act2 死亡，分类为 `clean_trainable/completed_clean`，失败归因为 `combat_planning`。它不是 `max-step` 截断，也不是外部数据接管导致；终局由 MCP null 后的 synthetic terminal recovery 记录，恢复成功。

本局价值很高：成功击败 Act1 The Guardian，并以 31 HP 进入 Act2，说明 Act1 入口策略在这局能过关；但进入 Act2 后，普通战和多敌压力处理仍不足。

## 受启发式/搜索影响的行为

- 路线、休息、奖励、药水、战斗动作仍主要来自旧 policy、route risk、potion tempo、direct lethal 和 one-turn search。
- Act1 Boss 前的牌组和路线判断使本局能打过 Guardian，这是启发式体系的正向样本。
- 战斗中大量 `one_turn_search` 只优化当回合损失、击杀和移除攻击，对 Act2 长线血量和下一场战斗风险估计不足。
- F20 死亡属于 Act2 续航和战斗规划失败，而不是执行 API 崩溃。

## 学习/模型影响

- 本局没有 `runtime_authority=true`，模型没有接管 live 出牌。
- combat value model 只作为 shadow metadata 记录，不改变动作。
- 本局进入训练后会提供一条“Act1 Boss 已通过、Act2 仍因 combat_planning 死亡”的正负混合样本，有助于把学习重点从 Act1 生存推进到 Act2 风险。

## 外部数据影响

- 外部 `mat1g3r_200_rotating_ironclad` 数据只参与 external prior 和 external blend 训练。
- 外部 prior 没有控制 live MCP，不进入 A0 gate、clean 判定或 learned memory 的权威来源。

## 后续影响

- 这局支持继续推进到“下一验证批”，但不能宣称 A0 已解决。
- 下一阶段应强化 Act2 普通战的未来损失估计，尤其是多敌、持续伤害和药水保留策略。
- 本局遇到的遗物/药水静态知识缺口已在本轮后补入知识库，后续训练特征应减少未知项。
